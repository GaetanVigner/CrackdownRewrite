# Crackdown on Any360: working rules for sessions

(Agents: this file is what a `CLAUDE.md` here would hold; the repository ignores `CLAUDE.md` files, so the local one only points here.)

This repository is Crackdown's port, a test bench for Any360 (github.com/GaetanVigner/Any360). The general rules are
Any360's `CLAUDE.md` and its skills (`.claude/skills/any360-native-function`, `.claude/skills/any360-perf-step`):
follow them here too. Talk to the owner in French; code, docs and commits in English. When the owner gives a new rule,
write it into this file (or Any360's `CLAUDE.md` when it is general) in the same change.

## Checkouts

- This worktree (`F:\Crackdown\crackdown-any360-sys`) builds against the Any360 checkout `F:\Crackdown\any360-gpu`
  (`CRACKDOWN_ANY360_DIR` in `build-any360/CMakeCache.txt`).
- Push to the fork: `git push fork HEAD:main HEAD:any360-sys-test`, after `git fetch fork` and rebasing on
  `fork/main`. Commit only your own files; never stash or revert another session's.

## Build

- After `vcvars64.bat`: `cmake --build build-any360 --target crackdown` (linking fails while `crackdown.exe` runs).

## Launch

- `build-any360\crackdown.exe --game_data_root=<worktree>\game\assets --user_data_root=<worktree>\build-any360\user_data
  --crackdown_skip_launcher=true --crackdown_skip_intro=true --any360_gpu=true
  --any360_sys_groups=stateless,files,objects,threads,memory,xam,input,audio`; logs in `build-any360\logs`.
- The title screen ignores Start above about 1,000 FPS: cap it (`--crackdown_frame_rate=60`) when the owner plays.
- Scripted route into the city (no gamepad needed): `--any360_input_script=12:start,16:a,20:a,24:a,28:a,32:a,40:a,50:a`.
  A launch whose loading outlasts the script stays on the title screen: drop it from an A/B.
- In-game D3D self-test: `--any360_d3d_selftest=true` (optionally `--any360_d3d_selftest_only=<name texts, comma
  separated, no spaces>`); the report is `build-any360\d3d_selftest.txt`, the process exits by itself.
- A/B launches: `tools\any360-ab.ps1` (minimized, variants alternating, "@exe:<name>" for a kept "before" build), then
  Any360's `tools/frame_lows.py <runs file> build-any360\logs`. When sessions share the machine, each uses the cores
  and GPU the owner gave it: `-Affinity 0xFF` (cores 0-7) and `-Device NVIDIA` (a substring of the Vulkan device name),
  and builds under the same mask (`cmd /c start "" /affinity FF /wait /b ...`).
- Hitches: `--any360_hitch_trace_ms=15` samples every thread while a frame runs over 15 ms (after 300 fast frames) and
  writes up to 5 `build-any360\logs\hitch_<n>.txt` reports, threads by CPU cycles with their stacks.
- Warn the owner before a visible launch; never capture the screen; stop only the processes your launches started.

## Every commit

- Regenerate the reports in the same commit: in the Any360 checkout
  `python -I tools/title_progress.py crackdown --out <worktree>/docs/progress --readme <worktree>/README.md`, then here
  `python -I tools/progress.py`.
- Bindings of Any360's natives live in `src/guest_bindings_base.cpp` (`CRACKDOWN_BIND_D3D`, the `Runtime` table,
  `ANY360_D3D_CASE` self-test cases); the title's own hooks that wrap a native call its `<Name>OrOriginal`.
